# Upstream Sources and Vendor Boundary

This file records where outside design research lives and how it enters the core skill. Load it when checking provenance, confidence, or why a rule exists. It is not required for ordinary builds.

## 1. Vendor boundary

The skill root contains `_vendor/apple-design-skills/`, an MIT-licensed snapshot of the `s1gmamale1/apple-design-skills` family. It is research material, not core guidance.

Rules:

- Core references distill; they do not load vendored files during normal use.
- Static scripts skip `_vendor/` by design.
- The vendored license stays intact at `_vendor/apple-design-skills/LICENSE`.
- No Apple-owned media is vendored or generated by the core skill.
- If a vendored rule conflicts with a core reference, the core reference wins.

## 2. Confidence translation

The upstream family labels claims as observed, documented, inferred, or speculative. Core references use Must / Should / May. Full translation lives in `evidence-apple-style.md`.

| Upstream label | Core treatment |
|---|---|
| documented | Cite the platform document when available; assign Must or Should by consequence. |
| observed | Treat as a dated observation with `[observed YYYY-MM-DD]`; assign Should unless repeated in platform docs. |
| inferred | Treat as analysis; label as inference and never promote to Must. |
| speculative | Keep in vendor only or mark as May with explicit uncertainty. |

Dated observations:

- Bundle internals and live-page behavior are snapshots, not constants.
- Exact pixel values from visual inspection are estimates. Canonical tokens win on conflict.
- Browser support changes. Re-test before promoting a browser-specific recipe to Should.

## 3. Editorial rule

A rule enters core docs only after it is rewritten as a platform-neutral behavior, paired with a native-platform mapping, and given a strength label.

Bad:

- copying an upstream paragraph wholesale
- presenting a reverse-engineered delivery detail as platform law
- turning a marketing-page effect into a universal app rule

Good:

- "Flagship marketing surfaces may use continuous scroll-bound motion; utility surfaces should keep scroll plain. Ship a reduced-motion replacement."
- "Background blur is a web approximation of a system material; use it only where native blur is unavailable and preserve contrast."

## 4. Exclusions

Do not promote these upstream items into core guidance:

- reverse-engineered server topology presented as official architecture
- dated bundle internals presented as permanent platform behavior
- exact marketing-page pixel estimates presented as canonical tokens
- third-party stack claims contradicted by direct bundle observation
- legal analysis presented as legal advice
- Apple-owned media, logos, device bezels, screenshots, or captured video frames

Keep the house rule instead: flagship craft may be studied, but shipped assets must be generated, self-owned, or permissively licensed.

## 6. Maintenance

When upstream changes:

1. refresh only the vendored snapshot when the license and provenance remain clear
2. diff distilled rules against the new snapshot
3. update the core reference that owns the domain
4. update `THIRD_PARTY.md` with the new snapshot date
5. run `npm run verify`
